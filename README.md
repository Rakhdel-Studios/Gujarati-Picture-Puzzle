# ચાર ચિત્ર એક શબ્દ — Gujarati Picture Puzzle

A "4 pictures, 1 word" game in Gujarati, built for **Gujarati-speaking seniors**.
Astro, static output, one interactive island, no framework.

Live at **https://picture-puzzle.rakhdel.games**

![The board](docs/board.png)

## Run it

```sh
npm install
npm run dev      # http://localhost:4321
npm run build    # -> dist/
npm run preview
npm test         # sense splitting + the data-contract invariants
```

## Data

Levels live in `src/data/levels.json` — the data pipeline's `dist/levels.json`
verbatim, an array ordered easiest-first:

```json
{
  "slug": "water",
  "english": "water",
  "gujarati": "પાણી",
  "tiles": ["પા", "ણી"],
  "decoys": ["ક", "મ", "તા", "રી"],
  "definition": "…Gujarati definition…",
  "images": ["1.webp", "2.webp", "3.webp", "4.webp"],
  "credits": []
}
```

Images go to `public/images/<slug>/1..4.webp`.

**The repo ships the real export: 87 levels, 4.4 MB of images** (flat editorial
illustrations generated by the pipeline, `flux2-klein-4b`, apache-2.0). Refresh
it after any pipeline run with:

```sh
npm run import-data -- ../PicturePuzzleDataGenerationPipeline/dist
```

That copies `levels.json` and the image tree into place and asserts
`tiles.join('') === gujarati` for every level. The zod schema in
`src/content.config.ts` then validates the whole contract at build time, so a
drift fails the build instead of shipping broken pages. `npm test` re-checks the
same invariants over whatever is currently in `src/data/levels.json`.

### Three things about the data the UI has to work around

- **`definition` is a full dictionary gloss, not a sentence** — 11 to 508
  characters, up to 27 comma-separated senses. It is split back into senses by
  `src/lib/senses.mjs` (paren-aware: a comma inside `(…)` is not a separator)
  and rendered as a numbered dictionary entry: first five senses in an `<ol>`,
  the tail in a quieter run-on line. Never dump it as one paragraph.
- **`english` is identical to `slug` on every record.** Render it once, as the
  translation. Do not print both as if they were separate facts.
- **`credits` is empty on every shipped level.** The render path exists and is
  conditional; do not build a prominent attribution feature on data that is not
  there yet. Full per-image provenance (prompt, seed, model, licence) lives in
  the pipeline's `dist/meta.json`.

### `tiles` is PRE-SPLIT. Never split Gujarati in the browser.

Gujarati is an abugida: `અઠવાડિયું` is 9 codepoints but **5 aksharas**
(અ / ઠ / વા / ડિ / યું). `[...word]` and `word.split("")` produce unreadable
fragments. The pipeline does the split; the site renders `tiles` verbatim.
Nothing in `src/` splits Gujarati text. If you ever truly need to segment
client-side, the only correct tool is
`new Intl.Segmenter('gu', { granularity: 'grapheme' })`.

## Non-negotiables

These are the product, not styling preferences. Read `src/styles/global.css`
and `src/components/Board.astro` before changing any of them.

- Base type ≥ 24px; tiles considerably larger.
- Touch targets ≥ 64px (`--tap`) with generous spacing. Mis-taps are the main
  frustration for this audience.
- High contrast, and **state is never signalled by colour alone** — border
  style and a text/glyph marker change too.
- **No timers, no lives, no streaks, no penalties.** A wrong answer simply does
  not lock in.
- Full keyboard operability; visible focus rings; focus is moved deliberately
  after every placement.
- Respects `prefers-reduced-motion`.
- Works one-handed at 400px.

Verified in headless Chromium against the built site: at 400px the base type is
24.4px, tiles are 33.6px glyphs in 72px boxes, and **zero** visible interactive
elements fall under 64px in either dimension, with no horizontal overflow.

The dictionary entry sits below the board and is always visible — it doubles as
the hint, so there is no gated hint system to nag anyone with. There is no score
to cheat at, so nothing is lost by it being readable.

## Ads

`src/components/AdSlot.astro` is a marked placeholder — no network code yet.
**Footer and between-levels only. Never inside or adjacent to the play area.**
The reasoning is in the component's comment; it is a safety constraint for this
audience, not a layout preference.

The artwork was generated with **FLUX.2-klein-4B**, which is released under
Apache-2.0 — a licence that places no restriction on the images the model
produces, so the outputs are ours to license. We put them under CC BY 4.0
rather than MIT because MIT is a software licence and says nothing useful about
pictures; CC BY is the right instrument for creative assets. Reuse them for
anything, including commercially — just credit *Rakhdel Studios*.

Per-image provenance (prompt, seed, model, licence) is recorded in the data
pipeline's `dist/meta.json`, not here.

No third-party photography ships in this repo. Some CC-licensed Openverse stock
exists upstream in the pipeline, but it is gated behind an explicit
`--include-openverse` flag and none of it reached this export — which is why
`credits` is empty on every level.

`src/data/levels.json` is generated data: the Gujarati words and definitions
derive from an open Gujarati lexical dataset, restructured by the pipeline.

## Deploy

`.github/workflows/deploy.yml` builds on push to `main` and deploys to GitHub
Pages via `withastro/action` + `actions/deploy-pages`.

1. Repo → **Settings → Pages → Source: GitHub Actions**.
2. Repo → **Settings → Pages → Custom domain**: `picture-puzzle.rakhdel.games`,
   then tick **Enforce HTTPS** once the certificate is issued.
3. `public/CNAME` already contains the domain, so it survives every build.

### DNS you must set

At the DNS host for `rakhdel.games`:

| Type  | Name             | Value                        |
| ----- | ---------------- | ---------------------------- |
| CNAME | `picture-puzzle` | `rakhdel-studios.github.io.` |

(Subdomain, so a `CNAME` is correct — the four `A` records are only for an apex
domain. If the zone is on Cloudflare, set the record to **DNS only / grey
cloud** until GitHub has issued the certificate.)

`astro.config.mjs` sets `site` to the full custom domain and leaves `base` at
`/`, which is right for a subdomain deploy — a `base` path is only needed for a
`user.github.io/repo` project page.
